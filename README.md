# CQA — Conversation Quality Analytics

Прототип для хакатона Freedom Broker: автоматическая оценка работы оператора в чатах и звонках по настраиваемому чек-листу, с обоснованием, ссылками на реплики, апелляциями и пересмотром.

## Быстрый запуск

Нужен Python 3.10+ (проверено на 3.12).

```bash
cd cqa
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env        # заполните DATA_API_URL и ANTHROPIC_API_KEY
.venv/bin/uvicorn --app-dir backend app:app --port 8000
```

Откройте http://localhost:8000.

1. На вкладке **Диалоги** введите `group_id` (например, `DEV`) и нажмите **Загрузить**. Диалоги загружаются через сервер, поэтому CORS не мешает.
2. Нажмите **Оценить набор**. Прогресс и стоимость видны в процессе.
3. Откройте диалог, чтобы увидеть транскрипт, итог, секции и критерии с обоснованием.

Без `ANTHROPIC_API_KEY` работает **демо-оценщик** на ключевых словах. Он нужен, чтобы проверить интерфейс без затрат, но содержательной оценки не даёт.

### Переменные окружения (`.env`)

| Переменная | Назначение |
|---|---|
| `DATA_API_URL` | Ссылка GET из задания. `group_id` подставляется автоматически |
| `ANTHROPIC_API_KEY` | Ключ Claude API |
| `CQA_EVALUATOR` | `claude` (по умолчанию при наличии ключа), `ollama` (локальная модель) или `heuristic` |
| `CQA_MODEL` | По умолчанию `claude-opus-5-5`; для Ollama, например, `qwen2.5:3b` |
| `CQA_EFFORT` | Глубина рассуждения модели: `low`, `medium` (по умолчанию) или `high` |
| `CQA_CONCURRENCY` | Сколько диалогов оценивается параллельно (по умолчанию 4) |
| `CQA_FALLBACKS` | `1`: при отказе модели запрос автоматически повторяется на резервной модели Claude |

## Что умеет

**Контур 1. Оценка**
- **Чек-лист.** Добавление, изменение и удаление критериев. У критерия настраиваются формулировка, вес, тип ответа (Да/Нет, шкала или флаг грубой ошибки), доступность N/A с условием, ступени шкалы и секции. Каждое сохранение создаёт новую версию, а прошлые оценки остаются привязаны к своей версии. Кнопка **Сохранить и оценить набор** применяет новый чек-лист к выбранному набору.
- **Оценка диалога.** Можно оценить один диалог или весь набор. Поддерживаются RU, KZ и EN. Реплики бота и системные события передаются модели как контекст.
- **Результат.** По каждому критерию показываются ответ, баллы до и после перераспределения, вес, объяснение и ссылки на реплики. Для пропущенного действия указывается проверенный участок, для N/A — причина. Внизу итог, баллы по секциям и отдельный флаг грубой ошибки.

**Контур 2. Работа с результатом**
- **Карточка диалога.** Клик по `#N` прокручивает транскрипт к реплике и подсвечивает её. У звонков встроенный плеер переходит к нужной секунде, а текущая реплика подсвечивается во время воспроизведения. Есть и ссылка на плеер организаторов.
- **Апелляция.** Под любым критерием есть кнопка «Оспорить оценку»: нужно добавить комментарий и сохранить.
- **Пересмотр.** На вкладке **Апелляции** проверяющий видит спорную оценку, комментарий и фрагмент диалога. Он подтверждает оценку или меняет её с указанием причины. Итог пересчитывается, а в карточке видны исходная оценка, решение и финальный результат.

## Как считается итог

Итог считает код в `backend/scoring.py`, модель только классифицирует. Правила взяты со стр. 2 чек-листа:

- «Да» даёт полный вес, «Нет» — 0.
- Шкала: `ступень / верхняя ступень × вес`.
- Критерии с N/A исключаются: итог = `Σ баллов / Σ весов применимых × 100`. Так вес N/A перераспределяется пропорционально, а максимум остаётся 100.
- Итог округляется до 2 знаков (половина округляется вверх). Если применимых критериев нет, итог не считается.
- Грубые ошибки (тип «флаг») в баллы не входят и отмечаются отдельно.

Тесты формулы: `cd backend && ../.venv/bin/python -m pytest -q tests`

## Модель и стоимость

- **Модель:** Claude Opus 5.5 (`claude-opus-5-5`) через официальный SDK `anthropic`. Используются строгий JSON-ответ по схеме чек-листа, кеширование системного промпта с чек-листом и серверный фолбэк при отказе модели.
- **Вызовы:** одна оценка = 1 вызов API.
- **Цена:** $4 за 1M входных токенов и $20 за 1M выходных. Точная стоимость каждой оценки считается по фактическим токенам и показывается в карточке, а для пакета — в прогресс-баре.
- **Оценка «на глаз»** (до замера на реальных ключах): около 4–8 тыс. входных и 2–4 тыс. выходных токенов, то есть порядка $0.05–0.10 за диалог. Звонки длиннее чатов и обходятся дороже.
- **Дешевле:** можно задать `CQA_MODEL=claude-sonnet-5-5` или `CQA_EFFORT=low`.
- **Без затрат:** `CQA_EVALUATOR=ollama` использует локальную модель, но качество ниже.

## Архитектура

```
backend/  FastAPI + SQLite
  app.py          HTTP API, пакетная оценка (пул потоков), апелляции, раздача фронтенда
  evaluator.py    промпт, JSON-схема ответа, вызов Claude / Ollama / эвристики
  scoring.py      детерминированный расчёт баллов, нормализация ответов
  datasource.py   загрузка наборов из API организаторов, ссылка на аудио
  default_checklist.json   исходный чек-лист из PDF
frontend/ HTML + CSS + ES-модули без сборки
  js/config.js    адрес API (apiBase)
  js/views/*.js   диалоги, карточка, апелляции, чек-листы
data/cqa.sqlite3  база (создаётся автоматически)
```

**Встраивание в Dynamics 365.** Фронтенд состоит из статических файлов без сборки, и все стили привязаны к `#cqa-root`. Файлы `index.html`, `css/app.css` и `js/**` публикуются как веб-ресурсы, а в `js/config.js` указывается `apiBase` с адресом сервиса оценки (CORS на сервере открыт).

**Звонки.** `audio_url` в наборе открывает HTML-плеер, внутри которого лежит временная ссылка на mp3 (живёт около часа). Сервер извлекает свежую ссылку при каждом открытии (`/api/audio/...`). Смещение реплики считается от первой ISO-метки звонка.

## Контрольный набор и замена критерия

1. **Загрузка.** Вкладка **Диалоги**: введите новый `group_id` и нажмите **Загрузить**, затем **Оценить набор**.
2. **Замена критерия.** Вкладка **Чек-листы**: измените критерий и нажмите **Сохранить и оценить набор**, указав `group_id`.
3. **Загрузка файлом.** Транскрипт можно загрузить JSON-файлом в формате API: запись, массив записей или ответ целиком.
